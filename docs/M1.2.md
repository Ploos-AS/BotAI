# M1.2 — second bot integration qualification

M1.2 extends the BotAI v1 integration profile from the first qualified Go bot (Engo) to a second implementation language and runtime.

## LuCa qualification

LuCa uses an optional native-C HTTP adapter. It does not embed Go and does not acquire a runtime dependency on BotAI.

Qualified evidence:

- repository: `Ploos-AS/LuCa`
- qualified LuCa commit: `9c3ecada281776e428752bd68d1a8ba8634cc843`
- GitHub Actions run: `36273087495`
- result: **PASS**
- LuCa qualification report added in commit `f8dd5720908b39410225b1dd5f96baa46c5b5068`

The qualification covers disabled/missing configuration, unreachable service, compatible and incompatible API versions, non-2xx responses, malformed version responses, bounded history, bounded responses and finite timeout behavior. The same adapter tests pass in normal Ubuntu CI and in the Alpine OCI Release build.

## Standalone-first invariant

LuCa remains a complete IRC bot without BotAI. IRC operation, Lua scripting and PBMP are independent of BotAI availability. BotAI is an optional adapter and may be removed without changing the core runtime architecture.

## Cross-language result

BotAI v1 is now qualified by:

- Engo — Go
- LuCa — C

This demonstrates that the protocol contract is not tied to the Go reference client.
