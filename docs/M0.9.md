# M0.9 — service hardening

M0.9 hardens BotAI for long-running service and OCI use.

The HTTP server now has explicit limits:

- read-header timeout: 5 seconds;
- read timeout: 15 seconds;
- write timeout: 60 seconds;
- idle timeout: 90 seconds;
- maximum request headers: 16 KiB;
- graceful shutdown budget: 15 seconds.

`SIGINT` and `SIGTERM` initiate graceful shutdown. Existing requests receive
a bounded opportunity to complete before the process exits.

Health endpoints are separated:

- `GET /healthz` is process liveness;
- `GET /readyz` reports whether BotAI has a provider and a usable expert
  registry.

Readiness deliberately does not make an upstream model request. A temporary
provider outage therefore affects AI requests but does not create probe-driven
provider traffic or restart loops.

Existing chat body/history/message limits remain in force.
