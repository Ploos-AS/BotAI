# M0.10 — stable API contract

M0.10 freezes the first BotAI HTTP contract before M1.

The stable API version is `1.0.0`. Existing v1 endpoints remain compatible:

- `POST /v1/chat`
- `GET /v1/experts`
- `GET /v1/status`

`GET /v1/version` returns the API contract version. The status response also
includes `api_version`.

The machine-readable contract is `api/openapi.yaml` using OpenAPI 3.0.3.
It documents health/readiness, status, experts, chat, metrics, request limits,
history roles and response shapes.

Compatibility rule for v1: additive fields and endpoints may be introduced,
but existing required request semantics and documented response fields must not
be removed or incompatibly changed. A breaking HTTP contract requires a new
major API path/version.

The service implementation version and API contract version are intentionally
separate concepts.
