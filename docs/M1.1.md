# M1.1 — integration profile and fail-open qualification

M1.1 defines how an IRC bot integrates BotAI without making AI a runtime
dependency of the bot core.

## Integration profile

A participating bot MUST:

1. start and connect to IRC when BotAI is disabled;
2. start and connect to IRC when BotAI is configured but unreachable;
3. keep ordinary IRC commands, ACLs, persistence and scripting/plugins working
   after a BotAI request fails;
4. expose AI commands/features only through an optional adapter;
5. check BotAI API compatibility before enabling AI features;
6. use bounded request history and a finite HTTP timeout;
7. avoid copying upstream/provider error bodies into IRC;
8. permit BotAI to be removed from the deployment without changing the bot core.

A bot MAY cache expert metadata, but a stale or unavailable expert registry must
not prevent normal IRC operation.

## Reference integration

For Go bots, `pkg/botaiclient` is the reference BotAI v1 client. Engo is the
first intended integration target and may import this package directly.

LuCa and AmBot should implement equivalent native HTTP adapters. They MUST NOT
embed Go merely to consume BotAI.

## Qualification matrix

| Case | Expected result |
| --- | --- |
| BotAI disabled | bot core PASS; AI unavailable |
| BotAI reachable, compatible v1 | bot core PASS; AI PASS |
| BotAI unreachable at startup | bot core PASS; AI unavailable |
| BotAI disappears at runtime | bot core PASS; AI request fails cleanly |
| BotAI returns non-2xx | bot core PASS; bounded status-only AI error |
| BotAI reports incompatible API | bot core PASS; AI disabled |
| history > 20 messages | request rejected locally |
| malformed/oversized response | AI request fails; bot core unaffected |

## M1.1 completion criteria

M1.1 is PASS when:

- the integration profile is documented;
- the reference client has explicit negative-path tests for unavailable,
  non-2xx and oversized responses;
- CI is green;
- one real bot (initially Engo) passes the qualification matrix.

Until the Engo integration and CI qualification are complete, M1.1 remains
IN PROGRESS.
